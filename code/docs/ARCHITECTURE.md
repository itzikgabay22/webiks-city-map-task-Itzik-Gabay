# CityMap Architecture

CityMap is the national public mapping platform of the Republic of Veloria, operated for Velorian Digital Services. It serves three audiences:

- **Residents and visitors** using the web map (anonymous, the vast majority of traffic).
- **Staff** of the planning department, who log in and see internal layers.
- **Integration partners** (transit operators, event apps, media) who pull public data through the partner API with an API key.

## Components

```
                         ┌──────────────── Kubernetes ────────────────┐
 browser / partner ──► CDN ──► load balancer ──► ingress-nginx ──┬──► api (NestJS)  ──┬──► PostGIS
                                                                 │                    └──► Redis (cache)
                                                                 └──► martin (tiles) ────► PostGIS
                                                    publisher (Job) ──────────────────────► PostGIS
```

| Component | What it does |
|---|---|
| `services/api` | Public REST API (NestJS, `pg`, `ioredis`). Stateless; scaled horizontally. |
| `tiles/` | [Martin](https://maplibre.org/martin/) vector tile server for the public data layers. District outlines are part of the static basemap and are not served by Martin. |
| `db/` | PostgreSQL 17 + PostGIS. Single SRID (EPSG:4326); every geometry column has a GiST index. |
| Redis | Response cache only. Nothing in Redis is data of record: losing it costs latency, never data. |
| `services/publisher` | Publishes official datasets into the `announcements` layer. Runs as a Kubernetes Job, on demand. |
| `services/sdk` | Client SDK used by partner integrations and by our own traffic generator. |
| CDN | CloudFront in production (see `deploy/terraform/aws-production`). Not present locally. |

Locally the ingress is reached at `http://localhost:8080`: `/api/*` goes to the API and `/tiles/*` to Martin. In production the same paths sit behind the CDN.

## Data layers

| Layer | Visibility | Local seed | Production | Notes |
|---|---|---|---|---|
| `parcels` | public | ~50k | ~41 million | Land parcels |
| `addresses` | public | ~100k | ~26 million | Searched by `/search/address` |
| `admin_boundaries` | public | 50 | ~14k | Districts locally; in production also municipalities and neighbourhoods, all at survey resolution. The northern coastal districts follow the surveyed coastline |
| `announcements` | public | per dataset | per dataset | Official datasets published by the publisher job |
| `planning_drafts` | private | 40 | ~12k | Owned by the planning department (`alice`), shared with `bob` |

Layer visibility is decided by `layers.is_public`, `layers.owner` and `layer_shares`.

The local seed is a small, deterministic sample generated by `make seed`. Production runs around the clock with no maintenance window: schema changes are applied by a migration job against the live database while traffic is flowing. Locally, `db/migrations` runs only when the database volume is first created.

## API

| Endpoint | Purpose |
|---|---|
| `GET /health` | Health check (also checks the database) |
| `POST /auth/dev-login` | Issues a token for a seeded user (local and staging only) |
| `GET /layers` | Layers visible to the caller |
| `GET /layers/:id/summary` | Aggregate statistics for a layer (heavy query, cached) |
| `GET /features/at?lon&lat&layers=` | "Click on the map": features under a point across layers (cached) |
| `GET /layers/:id/geojson?bbox&simplify=` | GeoJSON export with server-side simplification |
| `GET /search/address?q=` | Address lookup |
| `GET /partner/v1/features?bbox&layer=` | Partner API, `X-Api-Key` required, rate limited |
| `GET /announcements/latest` | The most recently published official dataset |

Anonymous callers need no token. Logged-in callers (staff) send `Authorization: Bearer <token>`: a JWT signed with a shared secret, valid for 8 hours. Partners authenticate with their API key.

## Policies that shape the design

- **Public data is open.** Public layers and tiles must be embeddable by any website without prior arrangement. Responses on public endpoints carry `Access-Control-Allow-Origin: *` on purpose.
- **Tiles are versioned by URL.** The web client requests `/tiles/{layer}/{z}/{x}/{y}?v={updatedAt}`, using the layer's `updatedAt` from `/layers`. When a layer changes, its tiles are fetched under a new URL, so tiles can be cached for a long time at the CDN.
- **Partners are first-class users.** Each partner has its own API key. Abuse and scraping should be limited without blocking legitimate partners.

## Publishing an official dataset

This is the flow behind events such as the Velorian Grand Prix announcement.

1. Velorian Digital Services hands over the dataset (road closures, detours, spectator zones, shuttle stops).
2. An operator runs the publisher (`make publish` locally; a Kubernetes Job in every environment). It writes the dataset into `announcements` under a new `dataset_version`, in one transaction, and bumps the layer's `updatedAt`.
3. The web map polls `GET /announcements/latest` and shows the newest dataset; partners read the same endpoint. The announcement layer's tiles pick up the new `updatedAt` automatically.
4. **The moment the publisher finishes, the dataset is official.** Residents, visitors and partners expect to see it right away, and the client communicates the publication time publicly.
